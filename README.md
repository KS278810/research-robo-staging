# ResearchRobo（Research KIT v5.2 ／ ライト版 v1.0）

**エンジニアのためのベンチマーク調査ツール。**
AIチャットに渡す1枚のMarkdownで、Deep Researchを単発検索ではなく
**再現可能・監査可能な証拠ベースの調査工程**に変える無料のプロンプトキットです。

紹介サイト: https://ks278810.github.io/research-robo/

## 使い方

LPの「手軽に試す」（ライト版・1チャット完結）または「しっかり調べる」（フル版・調査チャットで実行）ボタンを押すと、指示文と対応するKIT本文を結合したテキストがクリップボードにコピーされます。容量の大きいAIチャット（Gemini / Claude / ChatGPT有料プラン / 社内AI など。以下「最初のチャット」。最初のチャット自体はDeep Researchを使いません。Deep Researchは「しっかり調べる」で別のチャットが使います）に貼り付けて、そのまま送信してください。AIが調査テーマを質問してくるので、返信すれば調査が始まります。

Geminiは長文の貼り付けが不安定な場合があります。その場合は[`RESEARCH_KIT_v5.2.md`](./RESEARCH_KIT_v5.2.md)（手軽版は[`RESEARCH_KIT_lite_v1.0.md`](./RESEARCH_KIT_lite_v1.0.md)）をダウンロードして添付し、「この手順書に従ってください」と送信してください。

調査条件（目的・読者・対象・期間・対象外・決めたいこと・調査プロンプト数）が提示されるので、修正があれば伝え、なければ「OK」と返信してください。調査プロンプト数は既定3本前後ですが、数字で訂正すればその本数が優先されます（狭いテーマは1本、広いテーマでは対象をMECEに分けて数本になり、理由が示されます）。すると調査プロンプトが提示されます。**新しいチャットに貼り付けて、Deep Researchで実行してください。**同じチャットでDeep Researchを繰り返し起動できない（または不安定な）AIが多いため、調査は新しいチャットで行う設計です。複数本に分かれた場合は同時に開けば、その分だけ待ち時間を圧縮できます。

調査が終わった調査チャットに出てきたレポートを丸ごとコピーして、そのまま最初のチャットへ貼ってください。最初のチャットが資料・主張・未確認事項のコンパクトな行形式に変換して取り込みます（出典URLがほとんど無いレポートだけ、調査チャット自身への「一覧」依頼を案内します）。結果が長い場合は分割されるので、そのチャットに「次」と送って続きを貼ります。全部そろうと最初のチャットが統合・根拠確認（Blind Evidence Audit）を進めます（対象が広く分割された場合や、検証用のプロンプトが自動追加された場合は、同様に別チャットで実行します）。

レポートは最初のチャットが複数のコードブロック（`<!-- RR-PART k/n -->`〜`<!-- RR-END k/n -->`）に分けて返します。1つ届くごとに「次」と返信し、届いたコードブロックを順に[`viewer.html`](./viewer.html)へ貼ると、結合して整え、不備を確認し、その場でプレビュー・「PDFとして保存」ができます（ビューアは、貼り付けた内容をブラウザ内だけで処理し、サーバーには送信しません）。

ファイルや指示を保持できる作業スペース機能があるAIチャットなら、KITファイルを一度登録しておくと、2回目以降はファイルを添付し直す必要がなくなり、調査テーマを伝えるだけで始められます（任意・必須ではありません）。

## 入力した内容の行き先

手順書・調査テーマ・AIが返したレポートは、あなたが選んだAIチャットのサービス（外部）に送られます。社内情報や個人情報は、勤務先が使用を許可しているAIサービスでだけ扱ってください。AI側のデータの保存や学習への利用は、各サービスの設定と規約によります。
一方、`viewer.html`と`dispatch.html`は、貼り付けた内容をお使いのブラウザの中だけで処理し、サーバーには送信しません（`dispatch.html`はプロンプトの一覧と状態だけをブラウザに保存します）。アクセス解析（Google Analytics）はLP（`index.html`）だけで使っており、LPは表示のためにGoogle Fontsを読み込みます。

## できること（4つの技術的特徴）

1. **調べる前に軸を固める** — テーマを書くだけでAIが調査条件（目的・読者・対象・期間・対象外）を仮設定
2. **AIが仕様に応じて網羅的に調査** — 既定は調査対象をMECEに分け、数本（通常3本）のWork Packageとして各WPを別チャットで並行実行。狭いテーマだけ1本の自己完結プロンプトにまとめる。1つのチャットに文脈を溜め込まないため、調査品質が均等になり、トークン消費も抑えられる
3. **根拠のある情報だけ使う** — 出典位置・原文抜粋つきの構造化データで結果を回収し、Blind Evidence Auditで数値・帰属を検査
4. **そのまま渡せるレポートに** — 監査を通った事実だけで、出典番号つきのレポートを構成

## 社内ホスト（イントラネットでの配信）

`git clone` したままの内容を編集なしで社内に配信できます: Docker（`cd hosting && docker compose up -d --build`）、
Python 3だけのスクリプト（`python3 hosting/serve.py 8080 --host 0.0.0.0`）、GitHub Enterprise Server / GitLab
Pages のいずれでも対応しています。手順・注意点は [`hosting/README-hosting.md`](https://github.com/KS278810/research-robo/blob/main/hosting/README-hosting.md)
を参照してください（相対リンクだと、このREADME自体が配信された自己ホスト環境では
`hosting/`配下が意図的に配信拒否されており404になるため、GitHubの絶対URLにしている）。
コピーされるプロンプト内のビューアURL等は配信元のURLに自動で置き換わります。

# ResearchRobo（Research KIT v5.2 ／ ライト版 v1.0）

**エンジニアのためのベンチマーク調査ツール。**
AIチャットに渡す1枚のMarkdownで、Deep Researchを単発検索ではなく
**再現可能・監査可能な証拠ベースの調査工程**に変える無料のプロンプトキットです。

紹介サイト: https://ks278810.github.io/research-robo/

## 使い方

LPの「手軽に試す」（ライト版・1チャット完結）または「しっかり調べる」（フル版・調査チャットで実行）ボタンを押すと、指示文と対応するKIT本文を結合したテキストがクリップボードにコピーされます。Deep Research機能を持つAIチャット（ChatGPT / Claude / Gemini / 社内AI など。以下「最初のチャット」）に貼り付けて、そのまま送信してください。AIが調査テーマを質問してくるので、返信すれば調査が始まります。

Geminiは長文の貼り付けが不安定な場合があります。その場合は[`RESEARCH_KIT_v5.2.md`](./RESEARCH_KIT_v5.2.md)（手軽版は[`RESEARCH_KIT_lite_v1.0.md`](./RESEARCH_KIT_lite_v1.0.md)）をダウンロードして添付し、「この手順書に従ってください」と送信してください。

調査条件（目的・読者・対象・期間・対象外・決めたいこと・調査プロンプト数）が提示されるので、修正があれば伝え、なければ「OK」と返信してください。調査プロンプト数は既定1本ですが、数字で訂正すればその本数が優先されます（広いテーマでは自動で数本に分かれ、理由が示されます）。すると調査プロンプトが提示されます。**新しいチャットに貼り付けて、Deep Researchで実行してください。**同じチャットでDeep Researchを繰り返し起動できない（または不安定な）AIが多いため、調査は新しいチャットで行う設計です。複数本に分かれた場合は同時に開けば、その分だけ待ち時間を圧縮できます。

調査が終わった調査チャットに出てきたレポートを丸ごとコピーして、そのまま最初のチャットへ貼ってください。最初のチャットが資料・主張・未確認事項のコンパクトな行形式に変換して取り込みます（出典URLがほとんど無いレポートだけ、調査チャット自身への「一覧」依頼を案内します）。結果が長い場合は分割されるので、そのチャットに「次」と送って続きを貼ります。全部そろうと最初のチャットが統合・根拠確認（Blind Evidence Audit）を進めます（対象が広く分割された場合や、検証用のプロンプトが自動追加された場合は、同様に別チャットで実行します）。

レポートは最初のチャットが複数のコードブロック（`<!-- RR-PART k/n -->`〜`<!-- RR-END k/n -->`）に分けて返します。1つ届くごとに「次」と返信し、届いたコードブロックを順に[`viewer.html`](./viewer.html)へ貼ると、結合して整え、不備を確認し、その場でプレビュー・「PDFとして保存」ができます（貼り付けた内容はブラウザ内だけで処理され、どこにも送信されません）。

ファイルや指示を保持できる作業スペース機能があるAIチャットなら、KITファイルを一度登録しておくと、2回目以降はファイルを添付し直す必要がなくなり、調査テーマを伝えるだけで始められます（任意・必須ではありません）。

## できること（4つの技術的特徴）

1. **調べる前に軸を固める** — テーマを書くだけでAIが調査条件（目的・読者・対象・期間・対象外）を仮設定
2. **AIが仕様に応じて網羅的に調査** — 既定は1本の自己完結プロンプトにまとめ、広いテーマだけAIが自動でWork Packageに分割して各WPを別チャットで並行実行。1つのチャットに文脈を溜め込まないため、調査品質が均等になり、トークン消費も抑えられる
3. **根拠のある情報だけ使う** — 出典位置・原文抜粋つきの構造化データで結果を回収し、Blind Evidence Auditで数値・帰属を検査
4. **そのまま渡せるレポートに** — 監査を通った事実だけで、出典番号つきのレポートを構成

## 開発者向けメモ（配布運用）

ユーザー配布時の標準ファイルは上記表の8種類（`_latest.md`は同一内容の複製なので数に含めない）（`RESEARCH_KIT_vX.X.md` / `RESEARCH_KIT_lite_vX.X.md` / `viewer.html` / `dispatch.html` / `assets/js/rr-checks.js` / `assets/js/rr-report-css.js` / `benchmark-report-sample.pdf` / `REPORT_STYLE_SYNTHETIC.pdf`）のみとする。`rr-checks.js`・`rr-report-css.js`は`viewer.html`・`dispatch.html`の実装詳細であり、単独では意味を持たない（`<script src="assets/js/…">`でsame-origin読み込みされる前提。file://でも動作する）。

- 非ChatGPT環境向けの添付は`RESEARCH_KIT_vX.X.md`単体をそのまま使う。ZIP等のアーカイブ形式では配布しない（バイナリを展開できず解読不能と返すAIが実地で確認されている。2026-08）。添付は平文で読める単一ファイルを優先する。
- LPのコピーボタンは、同一オリジンの`RESEARCH_KIT_latest.md`（フル版）／`RESEARCH_KIT_lite_latest.md`（ライト版）（バージョン番号を含まない配布サイト常設ファイル）をJSで取得しプロンプトへ埋め込む。中身は`RESEARCH_KIT_vX.X.md`とバイト一致に保つこと。バージョン番号入りのURLをAI自身に取得させる方式は、検索エンジンの未インデックスにより取得失敗が発生することが実地確認されたため廃止した（2026-08）。
- KIT改訂時は、新しい`RESEARCH_KIT_vX.X.md`を作成した直後に`RESEARCH_KIT_latest.md`へ同一内容で上書きし、`diff`でバイト一致を確認する。ライト版も同様に`RESEARCH_KIT_lite_vX.X.md`→`RESEARCH_KIT_lite_latest.md`の同期を必ず行う。両KITはビューアと共有する契約（PARTマーカー・圧縮記法・トークン・構造ランドマーク）を持ち、その一致は`kit_contract.py`で機械検査する。
